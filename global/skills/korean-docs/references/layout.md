# 구조와 가시성

## 결론 먼저

첫 1~3줄에 결과, 결정, 요청 중 하나를 쓴다. 배경과 경위는 그 뒤에 둔다. 독자가 첫 3줄만 읽고 멈춰도 무엇을 해야 하는지 알 수 있어야 한다.

## 형식 선택

| 내용 | 형식 |
|---|---|
| 순서가 있는 절차 | 번호 목록 |
| 항목 3개 이상 × 속성 2개 이상 | 표 |
| 변경 전후 비교 | Before / After 표 |
| 서로 독립된 항목 나열 | 글머리 목록 |
| 이유, 인과, 판단 근거 | 짧은 문단 |
| 명령어, 설정, 로그 일부 | 코드 블록(언어 지정) |

## 헤딩

- 채널 본문(MR/PR, Jira)은 H2(`##`)부터 쓴다. H1은 기술 문서 제목에만 쓴다.
- 헤딩은 명사구로 쓴다(`검증 방법`, `원인`). 문장형, 이모지, 번호 접두사는 쓰지 않는다.
- 단계를 건너뛰지 않는다(H2 다음 H4 금지).

## 강조

- 굵게는 섹션당 1~2곳, 독자가 놓치면 안 되는 단어에만 쓴다. 문장 전체를 굵게 하지 않는다.
- 경고는 `> **주의**: ...` 한 줄로 쓴다.

## 길이

| 단위 | 상한 |
|---|---|
| 목록 항목 | 1줄 |
| 문단 | 3문장 |
| 표 셀 | 한 구절 |
| Jira 코멘트 | 약 15줄 |

상한을 넘으면 세부를 접거나(`<details>`, 렌더링되는 채널만) 별도 문서·MR 링크로 뺀다.

## 채널별 렌더링

| 문법 | GitLab / GitHub | Jira |
|---|---|---|
| Mermaid | 렌더링됨 | 렌더링 안 됨 → 표, 이미지, Artifact 링크 |
| `<details>` 접기 | 됨 | 안 됨 → 링크로 분리 |
| 체크박스 `- [ ]` | 됨 | 안 됨 → 일반 목록 |
| 표 | 됨 | 됨 |

## 기본 골격

템플릿이 없는 글은 다음 순서를 쓴다.

1. 요약 — 결과·결정·요청
2. 상세 — 근거, 경위, 비교
3. 확인 방법 — 독자가 직접 확인하는 절차
4. 남은 일 — 담당자와 함께
