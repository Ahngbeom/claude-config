# Jira 이슈

**언제 쓰나**: Jira에 버그나 작업 요청을 새로 등록할 때. 유형에 맞는 골격 하나를 고른다.

## 골격: 버그

```markdown
## 현상
<!-- 사용자가 겪는 문제 한두 줄. 넣지 말 것: 추정 원인, 코드 위치 -->

## 재현 절차
1. <!-- 화면·메뉴 이름 기준 단계 -->

## 기대 결과

## 실제 결과
<!-- 오류 문구, 화면 상태. 스크린샷이 있으면 첨부 -->

## 환경
<!-- 앱/웹, 버전, 기기·브라우저, 계정 유형, 운영/스테이징 -->

## 영향 범위
<!-- 누가, 얼마나 자주, 우회 방법 유무 -->
```

## 골격: 작업 요청

```markdown
## 배경
<!-- 왜 필요한지. 사용자·운영 관점 -->

## 목표
<!-- 끝났을 때 달라지는 것 -->

## 완료 조건
- <!-- QA가 확인할 수 있는 문장 -->

## 범위 밖
- <!-- 이번에 하지 않는 것 -->
```

## 예시 (버그)

```markdown
## 현상
로그인 상태로 하루 이상 지난 뒤 앱을 열면 "일시적인 오류" 화면이 뜹니다.

## 재현 절차
1. 앱에 로그인
2. 24시간 이상 앱 사용 안 함
3. 앱 다시 실행

## 기대 결과
로그인 화면으로 이동

## 실제 결과
"일시적인 오류가 발생했습니다" 화면에서 멈춤

## 환경
iOS 앱 3.12.0, 운영

## 영향 범위
장기 미접속 사용자 전체. 앱 재설치 시 해소됨
```

## 빈 섹션

- `범위 밖`: 경계가 분명하면 지운다
- 나머지 섹션은 모두 채운다. 모르는 값은 "확인 필요"로 쓴다
