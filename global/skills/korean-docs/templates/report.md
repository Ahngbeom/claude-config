# 보고서

**언제 쓰나**: 장애 보고, 조사·비교 분석, 의사결정 기록. 유형에 맞는 골격 하나를 고른다. 서술 어미는 `~다`, 헤딩은 H2부터, 섹션 순서는 골격 그대로 둔다.

## 골격: 장애 보고

```markdown
## 요약
<!-- 언제, 무엇이, 얼마 동안, 누구에게 영향을 줬는지 2~3줄. 현재 상태 포함 -->

## 영향
| 항목 | 내용 |
|---|---|
| 기간 | <!-- YYYY-MM-DD HH:MM~HH:MM KST (N분) --> |
| 범위 | |
| 규모 | <!-- 실패 건수, 영향 사용자 수 --> |

## 타임라인
| 시각 (KST) | 사건 |
|---|---|

## 원인
<!-- 직접 원인 → 그것을 막지 못한 이유. 사람이 아니라 과정을 쓴다 -->

## 조치
<!-- 복구를 위해 한 일 -->

## 재발 방지
| 조치 | 담당 | 기한 |
|---|---|---|
```

## 골격: 분석·비교

```markdown
## 결론
<!-- 권고안 한 줄과 핵심 이유 -->

## 비교
| 기준 | 안 A | 안 B |
|---|---|---|

## 근거
<!-- 측정값, 출처, 측정 조건 -->

## 권고
<!-- 다음 행동과 결정이 필요한 사람 -->
```

## 골격: 의사결정

```markdown
## 결정
<!-- 무엇을 하기로 했는지 한 줄, 결정일, 결정한 사람 -->

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|

## 선택 이유

## 후속 조치
- <!-- 담당, 기한 -->
```

## 예시 (장애 요약·영향)

```markdown
## 요약
2026-10-06 14:05~14:47 KST(42분) 예약 API 응답이 지연돼 예약 생성 약 320건이 실패했다. 14:40 롤백 후 14:47 정상화됐다.

## 영향
| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-06 14:05~14:47 KST (42분) |
| 범위 | 예약 생성 API |
| 규모 | 예약 생성 실패 약 320건, p95 응답 12초 |
```

## 빈 섹션

- 재발 방지의 담당·기한을 모르면 지어내지 않고 "미정"으로 쓴다
- 분석·비교의 선택지가 하나뿐이면 의사결정 골격을 쓴다
