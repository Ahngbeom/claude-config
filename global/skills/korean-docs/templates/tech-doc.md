# 기술 문서

**언제 쓰나**: README, 설계 문서, 런북, 가이드. 유형에 맞는 골격 하나를 고른다. H1 제목은 기술 문서에만 쓴다.

## 골격: README

```markdown
# <!-- 이름 -->

<!-- 무엇이고 누구를 위한 것인지 한 줄 -->

## 빠른 시작
1. <!-- 복사해 실행할 수 있는 명령 -->

## 사용법

## 설정
| 키 | 기본값 | 설명 |
|---|---|---|
```

## 골격: 설계

```markdown
# <!-- 주제 --> 설계

## 목표
## 비목표
## 구조
<!-- 구성 요소와 책임. 3개 이상 구성 요소가 상호작용하면 다이어그램 검토 -->
## 결정 사항
| 결정 | 이유 | 기각한 대안 |
|---|---|---|
```

## 골격: 런북

```markdown
# <!-- 작업 이름 --> 런북

## 언제 쓰나
<!-- 이 런북을 열게 되는 증상·알림 -->

## 사전 확인
- <!-- 권한, 접속 대상, 영향 범위 -->

## 절차
1. <!-- 명령 + 기대 출력 -->

## 롤백
1.

## 완료 확인
- <!-- 정상 상태를 판단하는 지표·명령 -->
```

## 골격: 가이드

```markdown
# <!-- 할 일 --> 가이드

<!-- 대상 독자와 끝나면 할 수 있게 되는 것 한 줄 -->

## 사전 준비
## 단계
1.
## 문제 해결
| 증상 | 원인 | 해결 |
|---|---|---|
```

## 예시 (런북 절차 일부)

````markdown
## 절차
1. 현재 배포 버전 확인
   ```bash
   kubectl -n booking get deploy booking-api -o jsonpath='{.spec.template.spec.containers[0].image}'
   ```
   기대 출력: `registry.example.com/booking-api:<버전>`
2. 배포 기록에서 직전 버전 태그 확인
````

## 빈 섹션

- README의 `설정`: 설정이 없으면 지운다
- 런북의 `롤백`: 지우지 않는다. 롤백이 불가능하면 그 사실과 이유를 쓴다
