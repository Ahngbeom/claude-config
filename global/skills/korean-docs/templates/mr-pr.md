# MR/PR 본문

**언제 쓰나**: GitLab MR, GitHub PR 설명을 쓸 때

## 골격

```markdown
## 요약
<!-- 무엇을 왜 바꿨는지 1~3줄. 넣지 말 것: 작업 경위, 커밋 목록 -->

## 먼저 볼 곳
<!-- 리뷰어가 가장 먼저 봐야 할 파일·판단 1~3개와 이유 -->

## 변경 사항
<!-- 동작 단위 목록. 파일 나열이 아니라 바뀐 동작을 쓴다 -->

## 검증 방법
<!-- 실행한 테스트·명령과 결과, 수동 확인 절차. 안 한 검증은 안 했다고 쓴다 -->

## 배포 순서·리스크
<!-- 순서 제약, 마이그레이션, 롤백 방법. 없으면 "없음" -->

## 관련 이슈
<!-- Jira 키 또는 링크 -->
```

## 예시

```markdown
## 요약
refresh token이 만료됐을 때 로그인 API가 500 대신 401을 반환하도록 수정합니다.

## 먼저 볼 곳
- `TokenService.refresh()`의 만료 예외 처리: 예외를 401로 바꾸는 지점

## 변경 사항
- 만료된 refresh token 요청에 401과 `TOKEN_EXPIRED` 코드 반환
- 만료 외 검증 실패는 기존대로 400 유지

## 검증 방법
- 단위 테스트 2개 추가: 만료 토큰 → 401, 위조 토큰 → 400
- 스테이징에서 만료 토큰으로 `/auth/refresh` 호출, 401 확인

## 배포 순서·리스크
없음. 프론트엔드는 401을 이미 처리함

## 관련 이슈
MOB-1423
```

## 빈 섹션

- `먼저 볼 곳`: 변경이 한 곳뿐이면 지운다
- `배포 순서·리스크`: 지우지 않는다. 없으면 "없음"
