# 한국어 문서 작성 스킬(`korean-docs`) 설계

- **날짜**: 2026-10-07
- **대상 repo**: `claude-config`
- **접근법**: 전역 스킬 + `sync-global.sh` 디렉터리 동기화 (브레인스토밍 접근 A)
- **상태**: 설계 확정, 스펙 리뷰 대기

## 1. 목표

사람이 읽는 한국어 글(MR/PR 본문, Jira 이슈·코멘트, 보고서·분석, 기술 문서·가이드)을 Claude가 쓸 때, 매번 지시하지 않아도 다음 네 가지가 보장되게 한다.

| 문제 | 스킬이 보장하는 것 |
|---|---|
| 채널 부적합 | 채널별 독자에 맞는 섹션 골격과 금지 항목 |
| 매번 형식이 다름 | 문서 종류별 고정 템플릿 |
| 구조·스캔성 부족 | 결론 먼저, 표·목록·헤딩 선택 기준, 길이 상한 |
| 문체·어투 | 어미 통일, 번역투 금지 목록, 용어·숫자 표기 규칙 |

**성공 기준**: 같은 입력으로 스킬 없이(기준선) 쓴 결과와 스킬을 적용해 쓴 결과를 비교했을 때, `checklist.md` 항목 위반이 기준선보다 줄고, 템플릿 섹션 순서가 매번 같다.

## 2. 비목표

- Slack 메시지, 커밋 메시지 — 각각 `slack:slack-messaging`과 `global/CLAUDE.md` Git 규칙이 담당한다.
- 영어 문서 — 한국어 문서만 대상. 영어 요청 시 스킬은 적용하지 않는다.
- 문서 게시 자동화(Jira/GitLab API 호출) — 본문 작성까지만 한다.
- 자동 lint 스크립트 — 이번 범위는 규칙·템플릿·자가 검수. 위반이 반복되면 후속으로 검토한다.

## 3. 현 상태

- `productivity-agents`에 `/write-docs` 커맨드와 `markdown-document-writer` 에이전트(haiku)가 있다. 둘 다 범용 마크다운 서식 규칙만 담고 채널·한국어 문체를 다루지 않으며, 같은 규칙이 두 파일에 중복돼 있다.
- `productivity-agents` 플러그인은 이 머신에서 비활성이다. 플러그인 스킬로 만들면 지금 동작하지 않는다.
- `global/CLAUDE.md`의 "Audience by Channel" 표가 채널별 독자·첫머리·제외 항목의 원본이다.
- `scripts/sync-global.sh`는 파일 3개만 개별 동기화한다. 디렉터리는 지원하지 않는다.
- `scripts/validate.sh` 6번 검사가 레포 전체의 `SKILL.md` frontmatter(`name`, `description`)를 이미 검사한다.

## 4. 구조

```
global/skills/korean-docs/
├── SKILL.md
├── references/
│   ├── style.md
│   ├── layout.md
│   └── checklist.md
└── templates/
    ├── mr-pr.md
    ├── jira-issue.md
    ├── jira-comment.md
    ├── report.md
    └── tech-doc.md
```

설치 위치는 `~/.claude/skills/korean-docs/`이며 `scripts/sync-global.sh push`로 배포한다.

### 4.1 원본 단일화

| 정보 | 원본 | 스킬에서의 처리 |
|---|---|---|
| 채널별 독자, 첫머리, 제외 항목 | `global/CLAUDE.md` "Audience by Channel" | 다시 적지 않는다. 템플릿의 섹션 순서와 "넣지 말 것" 주석으로 구현한다 |
| 다이어그램 제안 여부 | `global/CLAUDE.md` Visuals 항목 | 다시 적지 않는다. SKILL.md 절차에서 "해당 규칙 확인" 한 줄로만 연결한다 |
| 한국어 문체, 레이아웃, 템플릿, 검수 | 이 스킬 | 원본 |

## 5. 구성 요소

### 5.1 `SKILL.md`

- **frontmatter**: `name: korean-docs`, `description`은 트리거 조건만 적는다. 무엇을 하는지 요약하지 않는다. 트리거 예: "한국어로 MR/PR 본문, Jira 이슈·코멘트, 보고서, 분석, 설계 문서, README, 가이드, 런북을 작성하거나 다듬을 때".
- **본문**(목표 80줄 이하):
  1. 문서 종류 판별 → 템플릿 라우팅 표(종류 → 파일)
  2. 작성 절차: 템플릿 읽기 → `style.md`·`layout.md` 적용 → 초안 → `checklist.md` 검수 → 수정 후 제출
  3. 핵심 규칙 5줄 이내 요약(결론 먼저, 어미 통일, 번역투 금지, 독자 확인, 검증 명시)
  4. 템플릿에 맞지 않는 문서: `layout.md` 기본 골격 사용

### 5.2 `references/style.md` — 문체

- **어미**: 채널별 기본 어미를 정하고 한 문서 안에서 섞지 않는다.

  | 채널 | 기본 어미 |
  |---|---|
  | Jira 코멘트, MR/PR 본문 | 합쇼체 서술 + 목록은 명사형 종결(`~함`, `~완료`) |
  | 보고서, 기술 문서 | 평서형 `~다` |
  | 목록·표 셀 | 명사형 종결, 마침표 없음 |

- **번역투 금지 목록**: Before/After 표로 20개 내외. 예: `~에 대해서` 남용, `~를 가지다`(have), `~되어지다` 이중 피동, `~하는 것이 가능하다`, `~에 있어서`, `~를 통해` 남용, 불필요한 `그`/`해당`, `~적인` 남용, 무생물 주어 + 타동사.
- **장황함 제거**: 수식어(`매우`, `다양한`, `효과적으로`), 메타 서술(`아래와 같이 정리하였습니다`), 같은 내용 반복 금지.
- **용어 표기**: 코드 식별자·제품명은 원문 + 백틱. 외래어는 국립국어원 표기를 따르되 업계 통용 표기가 굳은 경우(예: `서버`, `배포`) 그대로 둔다. 같은 개념은 문서 안에서 한 표기만 쓴다.
- **숫자·날짜·단위**: 날짜 `2026-10-07`, 시각 `14:30 KST`, 숫자와 단위 붙여 쓰기(`3초`, `200ms`), 상대 시점(`어제`, `지난주`) 금지.
- **띄어쓰기**: 자주 틀리는 항목만 짧은 표로(`~할 수 있다`, `~하는 데`, `~뿐`, `~만큼` 등).

### 5.3 `references/layout.md` — 구조·가시성

- **결론 먼저**: 첫 1~3줄 안에 결과·결정·요청 사항. 배경은 그 뒤.
- **형식 선택 기준**:

  | 내용 | 형식 |
  |---|---|
  | 순서가 있는 절차 | 번호 목록 |
  | 3개 이상 항목 × 2개 이상 속성 | 표 |
  | 변경 전후 비교 | Before/After 표 |
  | 독립 항목 나열 | 글머리 목록 |
  | 인과·근거 설명 | 짧은 문단(3문장 이하) |

- **헤딩**: H2부터 시작(채널 본문에는 H1 없음, 기술 문서만 H1 제목). 헤딩은 명사구, 이모지 금지.
- **강조**: 굵게는 한 섹션에 1~2곳, 문장 전체 굵게 금지.
- **길이 상한**: 목록 항목 1줄, 문단 3문장, Jira 코멘트 화면 한 번에 들어오는 분량(약 15줄). 넘으면 세부를 접기(`<details>`, 렌더링되는 채널만) 또는 링크로 분리.
- **채널별 렌더링 차이**: GitLab/GitHub는 Mermaid·`<details>` 지원, Jira는 미지원(표·이미지·링크로 대체). 체크박스 `- [ ]`는 GitLab/GitHub에서만.
- **기본 골격**(템플릿 없는 문서): 요약 → 상세 → 확인 방법 → 남은 일.

### 5.4 `references/checklist.md` — 게시 전 자가 검수

각 항목은 예/아니오로 답할 수 있게 쓴다. 그룹: **독자**(채널 독자가 코드를 열지 않고 행동할 수 있는가), **구조**(첫 3줄에 결론, 형식 선택 기준 준수, 길이 상한), **문체**(어미 혼용 없음, 번역투 목록 해당 없음, 상대 시점 없음, 용어 표기 일관), **사실**(완료라고 쓴 항목마다 검증 방법이 적혀 있는가, 미검증은 그렇게 명시했는가), **채널**(렌더링 안 되는 문법 미사용, 템플릿의 "넣지 말 것" 항목 없음).

### 5.5 `templates/*.md`

모든 템플릿은 같은 형태를 따른다.

1. **언제 쓰나** — 1줄
2. **골격** — 복사해 채우는 마크다운 블록. 섹션별 `<!-- 채울 내용 / 넣지 말 것 -->` 안내 주석 포함. 제출 시 주석은 지운다
3. **예시** — 채워진 짧은 예시 1개
4. **빈 섹션 규칙** — 해당 없는 섹션은 지운다. "해당 없음"으로 남기지 않는다(단, 리스크·배포 순서처럼 "없음" 자체가 정보인 섹션은 예외로 명시)

| 템플릿 | 섹션 골격 |
|---|---|
| `mr-pr.md` | 요약 → 먼저 볼 곳 → 변경 사항 → 검증 방법 → 배포 순서·리스크 → 관련 이슈 |
| `jira-issue.md` | 유형 분기: **버그**(현상 → 재현 절차 → 기대 결과 → 실제 결과 → 환경 → 영향 범위), **작업 요청**(목표 → 배경 → 완료 조건 → 범위 밖) |
| `jira-comment.md` | 유형 분기: **진행**(현재 상태 → 다음 단계 → 막힌 점), **완료**(변경 결과 → 확인 방법 → 남은 일 → MR 링크) |
| `report.md` | 유형 분기: **장애**(요약 → 영향 → 타임라인 → 원인 → 조치 → 재발 방지), **분석·비교**(결론 → 비교표 → 근거 → 권고), **의사결정**(결정 사항 → 선택지 비교 → 선택 이유 → 후속 조치) |
| `tech-doc.md` | 유형 분기: **README**(무엇인가 → 빠른 시작 → 사용법 → 설정), **설계**(목표 → 비목표 → 구조 → 결정 사항), **런북**(언제 쓰나 → 사전 확인 → 절차 → 롤백 → 확인), **가이드**(대상 독자 → 사전 준비 → 단계 → 문제 해결) |

## 6. 동기화·검증 변경

### 6.1 `scripts/sync-global.sh`

- `FILES` 배열 옆에 `DIRS=("skills/korean-docs")`를 추가한다.
- `push`: 대상 디렉터리에 다른 내용이 있으면 `~/.claude/sync-global-backups/<dir>-<timestamp>`로 백업한 뒤 `rsync -a --delete`로 미러링. `skills/` 안에 두면 같은 이름 스킬이 중복 로드되고, `backups/`는 `cleanup.sh`가 최신 1개만 남기고 지우므로 둘 다 피한다. `rsync`는 macOS·CI 기본 설치라 필수 의존성으로 둔다.
- `pull`: 역방향 미러링. 대상이 없으면 `MISSING`, 레포 쪽 디렉터리에 커밋하지 않은 변경이 있으면 `REFUSED`로 중단한다.
- `check`: `diff -r`로 drift 검출.
- `DIRS`는 명시 목록이다. `~/.claude/skills/` 전체를 동기화하지 않는다(다른 도구가 설치한 스킬이 섞여 있다).

### 6.2 `scripts/validate.sh`

- 6번 검사가 이미 `find . -name SKILL.md`로 `global/skills`를 포함한다. 추가로:
  - `SKILL.md`의 `name`이 디렉터리명과 같은지
  - `SKILL.md`가 참조하는 `references/*.md`, `templates/*.md` 경로가 실제로 존재하는지

### 6.3 레포 문서

- `CLAUDE.md` Layout 표의 `global/` 설명에 `skills/` 추가, "This repo currently ships commands only" 문장을 전역 스킬 존재에 맞게 수정.
- `README.md`: 전역 스킬 항목 추가.

## 8. 검증 계획

1. `scripts/validate.sh` 통과
2. `scripts/sync-global.sh push` 후 `check`가 `global in sync`
3. `rg -n "write-docs|markdown-document-writer"` 결과가 과거 스펙 파일 외에 없음
4. **스킬 품질(writing-skills 방식)**: 같은 시나리오 3개(MR 본문, Jira 완료 코멘트, 장애 보고서)를 서브에이전트로 스킬 없이 한 번, 스킬을 적용해 한 번 작성. `checklist.md`로 두 결과를 채점해 위반 수를 비교하고 결과를 MR 본문에 기록
5. 새 세션에서 "이 변경 MR 본문 써줘" 요청 시 스킬이 자동 호출되는지 확인

## 9. 가정·리스크

- **가정**: 스킬 자동 호출은 `description` 매칭에 의존한다. 호출이 누락되면 `global/CLAUDE.md` "Audience by Channel" 근처에 스킬을 가리키는 한 줄을 추가하는 것을 후속으로 검토한다(이번 범위에서는 추가하지 않는다 — 검증 5에서 누락이 확인될 때만).
- **리스크**: `sync-global.sh push`가 디렉터리를 미러링하므로, `~/.claude/skills/korean-docs/`를 레포 밖에서 직접 고치면 다음 push에서 덮인다. 백업 디렉터리로 복구 가능.
- **리스크**: 규칙이 많아지면 모델이 일부를 놓친다. `SKILL.md` 핵심 규칙은 5줄로 제한하고 나머지는 검수 단계에서 잡는다.
